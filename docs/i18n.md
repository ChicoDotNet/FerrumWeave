# FerrumWeave documentation internationalization

FerrumWeave treats documentation accessibility as part of interoperability.

The project should not require native English fluency to participate in .NET language engineering. English remains the canonical documentation source so that translations have one stable semantic origin, but contributors and readers should be able to enter the project through their own language wherever practical.

## Canonical naming convention

The unsuffixed document is the canonical English source:

```text
README.md
docs/getting-started.md
docs/roadmap/template-release-plan.md
```

Translations keep the canonical basename and add a BCP-47 language tag immediately before `.md`:

```text
README.de.md
README.es.md
README.fr.md
README.it.md
README.pt-BR.md
README.ru.md
README.zh-Hans.md
README.ja.md

docs/getting-started.es.md
docs/roadmap/template-release-plan.ja.md
```

Do not translate filenames themselves. Human-facing language selectors use native language names instead of locale codes.

## Translation provenance

Translated Markdown files should begin with an HTML comment that records their canonical source and source revision:

```html
<!--
translation-of: README.md
locale: es
source-revision: <commit-or-blob>
-->
```

The metadata is intentionally invisible in rendered Markdown and is designed to support a future CI stale-translation check.

## Semantic rules

- Preserve technical meaning rather than translating word-for-word when that would be unnatural.
- Do not translate identifiers, commands, package names, project names, API names, code, file extensions, or compiler/runtime terminology that is normally used verbatim.
- Keep examples executable and byte-for-byte equivalent where the example itself is part of a contract.
- Translate explanatory comments inside illustrative code only when doing so cannot change the executable contract.
- Preserve warnings about unreleased or target behavior in every language.
- Prefer links to the same-language document when that translation exists; otherwise link to the canonical English source.
- English documentation remains authoritative when a translation temporarily lags behind.

## Staleness policy

A translated document may temporarily lag behind its canonical source, but this must be visible to tooling. Initially, stale translations should produce a warning rather than block unrelated engineering work. Once translation automation is mature and reliable, individual documentation surfaces may opt into stricter gates.

## Cultural principle

> Documentation is maintained in multiple languages because interoperability is about people, too.

FerrumWeave aims to connect Rust and .NET without forcing either ecosystem to pretend to be the other. The same principle applies to contributors: technical rigor should not be confused with native-English fluency.
